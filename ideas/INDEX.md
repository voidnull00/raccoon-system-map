# Ideas — Thinking Primitives

This folder contains named thinking patterns.

They are not features, systems, or specifications.

They are:

> **mental models used to guide decisions, evaluation, and system behavior**

---

## Purpose

These ideas serve as:

- lightweight thinking tools
- reusable patterns across contexts
- clarity mechanisms in complex or ambiguous situations

They are intentionally:

- minimal
- abstract
- non-prescriptive

---

## Core Set

### 1. Rangespeaking

→ [rangespeaking/rangespeaking.md](rangespeaking/rangespeaking.md)

Evaluates decisions on a spectrum instead of binary outcomes.

> “Where does this sit on a range?”

Used for:

- evaluating quality
- comparing variations
- making non-binary decisions

---

### 2. Latent Constrained Vectors

→ [latent-constrained-vectors/latent-constrained-vectors.md](latent-constrained-vectors/latent-constrained-vectors.md)

Stores ideas as inactive directions with activation conditions.

> “This exists, but only becomes relevant if X is true”

Used for:

- avoiding premature system growth
- bounding low-probability ideas
- reducing cognitive noise

---

### 3. Conditional Attribution

→ [conditional-attribution/conditional-attribution.md](conditional-attribution/conditional-attribution.md)

Applies attribution only when it adds clarity or reduces risk.

> “Does attribution improve understanding here?”

Used for:

- maintaining flow in iteration loops
- avoiding unnecessary meta-discussion
- simplifying collaboration

---

### 4. Recognizable Presence Across States

→ [recognizable-presence-across-states/recognizable-presence-across-states.md](recognizable-presence-across-states/recognizable-presence-across-states.md)

Maintains identity stability across variable outputs without requiring exact sameness.

> "Does this still feel like the same source?"

Used for:

- evaluating creative outputs
- selecting between variants
- calibrating judgment under variation

---

## Interface Patterns

### Thinking Layer — Q&A Interface Pattern

→ [observability_thinking_layer/THINKING_LAYER\_\_Q&A_Interface_Pattern.md](observability_thinking_layer/THINKING_LAYER__Q&A_Interface_Pattern.md)

Wraps raw Q&A in structured context to produce decision-ready output.

> "What decision does this thinking lead to?"

Used for:

- gate validation
- deliverable evaluation
- direction checks

---

## Relationship Between Primitives

These patterns operate on different layers:

```txt
Rangespeaking           → evaluation layer
Latent Vectors          → activation layer
Conditional Attribution → communication/meta layer
Recognizable Presence   → identity/continuity layer
Thinking Layer          → decision interface layer
```

Together, they form a minimal set of:

> **decision-support primitives**

---

## How to Use

These are not rules.

They are:

> tools to be applied when useful

Guideline:

```txt
if (pattern reduces friction or improves clarity):
    apply
else:
    ignore
```

---

- a framework
